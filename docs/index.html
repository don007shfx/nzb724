A new service is one file.

Every integration maps one service's API onto the same four shapes: library, queue, search and add. The interface reads what a plugin declares, so a service that has no queue never grows a queue button.

  • Capabilities are a promise: declare one you did not implement and the registry refuses to load you.
  • One failing service shows a note in its own row; the rest of the screen still loads.
  • Calls go through a small context object, so adapters never touch fetch or credentials.
Read the plugin contract
builtin/readarr.ts plugin 
export const readarr: IntegrationPlugin = {
  apiVersion: 1,
  meta: {
    id: 'readarr',
    kind: 'media',
    defaults: { scheme: 'http', port: 8787, path: '' },
    capabilities: { library: true, queue: false,
                    search: true, add: true },
  },

  async test(ctx) {
    const status = await ctx.get('/api/v1/system/status');
    return { ok: true, version: status.version };
  },

  async library(ctx) {
    const authors = await ctx.get('/api/v1/author');
    return authors.map(toMediaItem);
  },
};
